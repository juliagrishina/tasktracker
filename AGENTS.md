# Правила работы с репозиторием

1. Перед изменениями читать `docs/requirements/ТЗ_iOS_планировщик_MVP.docx` и актуальную спецификацию в `docs/superpowers/specs/`.
2. Не расширять объём MVP без явного согласования.
3. Не добавлять запись в Outlook и не запрашивать права выше `Calendars.Read`.
4. Не коммитить секреты, токены, локальные сессии Superpowers, Xcode user data и временные файлы.
5. После содержательных изменений запускать релевантные проверки, создавать понятный Git-коммит и отправлять текущую ветку в GitHub.
6. В отчёте указывать commit SHA, результаты проверок и оставшиеся ограничения.

## Безопасная работа с Trello REST API

1. Использовать `TRELLO_API_KEY` и `TRELLO_TOKEN` только из локального `.env` вне репозитория; никогда не печатать содержимое `.env` или значения этих переменных.
2. Не выводить полные Trello URL и query string, если в них есть `key`, `token` или другие секреты; не выводить Authorization headers либо другие headers с учётными данными.
3. Не печатать команды, в которых секреты уже подставлены открытым текстом, и не допускать их попадания в stdout/stderr, диагностический вывод, логи или финальный ответ.
4. При диагностике показывать только безопасные данные: HTTP status code, название операции и очищенный ответ API. Если выбранный способ запроса может раскрыть секреты, использовать другой способ.
5. Никогда не коммитить `.env` или другие файлы с секретами. Перед изменяющими запросами к Trello по возможности проверять подключение безопасным GET-запросом.
6. Пользовательские поля Trello недоступны и не используются. При создании или обновлении карточки записывать `Epic`, `Type`, `Priority`, `Severity` и `Owner` в начале её описания по Trello Workflow Protocol и подтверждать read-back описания.
