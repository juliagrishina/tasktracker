# Epic 11 — надёжный offline-start и брендовые assets

**Статус:** согласовано для детализации 2026-09-13
**Связанные документы:** `docs/tz/account-authentication-and-cloud-sync.md`, `docs/tz/epic-09-quality-accessibility-and-release.md`, `docs/superpowers/specs/2026-09-10-e11-t29-offline-pwa-shell-design.md`

## Цель

После первого успешного онлайн-входа установленная PWA должна открываться без сети из локальной реплики аккаунта и позволять продолжить работу. Сеть нужна для регистрации, входа на новом устройстве и фоновой синхронизации, но не для первого кадра, чтения IndexedDB, отображения сохранённых задач или постановки изменений в outbox.

Параллельно приложение получает единый комплект брендовых иконок и устраняются три визуальные ошибки: неотрисованная дуга загрузки, обрезанные кнопки редактора и повторная дата первого временного блока.

## Зафиксированные причины наблюдаемого поведения

1. `AuthGate` ждёт `Supabase.auth.getSession()` до выбора области данных. При офлайн-обновлении токена этот Promise может долго не разрешаться, оставляя стартовый `ActivityIndicator` без статуса и без перехода к локальным данным.
2. `AppServicesProvider` вызывает `syncNow()` до чтения локальных настроек, задач, выполненных элементов и энергии. Недоступная сеть тем самым задерживает открытие экрана, хотя IndexedDB уже содержит рабочую реплику.
3. Экран настроек сначала создаёт профиль через удалённый `getSession()`. При сетевой ошибке он подменяет доступный локальный аккаунт состоянием `withoutAccount`, хотя активная account-scoped реплика остаётся доступна.
4. `ProgressRing` передаёт SVG dash-array строкой; на затронутом iOS runtime активный сегмент кольца не рисуется. Полоса использует другой механизм и поэтому отображает красный тон корректно.

## Границы и инварианты

- Режим «только авторизация» сохраняется. Экран не возвращает вход без аккаунта и не создаёт новую автономную область.
- Локальная account-scoped область не является доказательством удалённой авторизации на новом устройстве. Она разрешает только продолжение ранее подтверждённой сессии на этом устройстве.
- Офлайн-режим не выдаёт ложное состояние «Без аккаунта». Если есть подтверждённая локальная область и профиль, интерфейс показывает имя/email с признаком локального офлайн-режима.
- Удаление/выход подтверждённым сервером остаются единственными действиями, которые скрывают локальную account-scoped область. Ошибка сети, таймаут обновления токена или временно просроченный access token её не удаляют.
- Локальные изменения записываются в IndexedDB и durable outbox до сетевого вызова. Sync запускается после готовности UI и не является условием первого отображения.
- Не меняются Supabase schema/RLS, Redirect URLs, EAS environment variables, production deployment и политика очистки данных.
- Исторический `docs/requirements/ТЗ_iOS_планировщик_MVP.docx` не используется и не изменяется.

## Поток запуска

1. PWA shell и boot-screen показывают брендовый знак, краткое сообщение и stage-based progress.
2. Gate читает сохранённый локальный session snapshot и реестр активной data scope. Он не ждёт сеть, чтобы открыть уже известную account scope.
3. Если локальная account scope подтверждена кэшированным профилем, Gate открывает её и передаёт удалённую проверку/refresh в фон. Если профиль отсутствует или scope не подтверждена, показывается обычный экран входа.
4. `AppServicesProvider` сначала открывает IndexedDB и читает локальные данные. После этого выставляет `isReady=true` и даёт пользователю рабочий UI.
5. Затем запускается sync. Успех обновляет `lastSuccessAt` и профиль; сетевой сбой только устанавливает sync-status/offline-status и сохраняет outbox.
6. При событии `online` или возвращении приложения на передний план запускается повторная проверка сессии и sync. Подтверждённый remote sign-out переключает Gate в экран входа; простой сбой сети — нет.

## Статус загрузки

Boot-screen использует конечные этапы, а не симулирует сетевую загрузку:

| Прогресс | Сообщение | Реальное условие |
| --- | --- | --- |
| 15% | «Восстанавливаем доступ» | прочитан локальный session/scope state |
| 45% | «Открываем локальную копию» | открыта IndexedDB область |
| 75% | «Загружаем ваши планы» | прочитаны local settings/backlog/completed/energy |
| 100% | «Готово» | UI доступен; sync работает отдельно |

Если IndexedDB действительно недоступна или повреждена, пользователь получает понятный error-state с действием повторить запуск; бесконечного spinner не остаётся.

## Локальная идентичность и профиль

- При онлайн-регистрации или входе записывается cache профиля (`userId`, имя, email, подтверждение email, pending email) для account scope.
- В settings сначала показывается кэш, затем выполняется фоновое обновление. Remote failure не перезаписывает кэш `withoutAccount`.
- Изменение имени/email/пароля остаётся онлайн-действием. В офлайне controls сообщают, что действие будет доступно после сети; текущие имя и email не исчезают.
- Кэш профиля связан с `accountId`, поэтому его нельзя применить к другой account scope.

## Брендовые assets

| Источник | Назначение | Производные размеры |
| --- | --- | --- |
| Переданный `1.png` | иконка приложения, Apple touch icon, логотип boot/auth | master 1024px; 512px, 192px, 180px, компактный auth/boot вариант |
| Переданный `2.png` | favicon и мелкий браузерный знак | 512px master и favicon-derived PNG |

Изображения нормализуются без изменения их текста, цветов или композиции: обрезается только внешний белый край, сохраняется прозрачность/контраст, а нужные bitmap-версии размещаются в репозитории. `app.json`, web manifest, `+html` и auth/boot UI используют соответствующие производные assets.

## Визуальные и редакторские уточнения

- `ProgressRing` использует числовой SVG dash-array/dash-offset и один поворот вокруг центра. При нагрузке 92% видимая красная дуга равна 92%; текст и строка progressbar остаются доступными screen reader.
- Когда в редакторе доступны четыре действия, footer становится сеткой 2×2 с полной подписью и высотой каждого action не менее 44px. В режимах с одним/двумя действиями сохраняется компактная горизонтальная компоновка.
- В date-mode первый блок наследует `Дата задачи`: дата для него не дублируется и при изменении даты задачи меняется вместе с ней. У блоков №2 и далее дата показывается и редактируется независимо.

## Проверка

- Unit/UI: offline recovery account scope, timeout/remote failure не очищает account state, cache-first profile, local-first provider bootstrap, boot stage labels, error/retry, SVG 92% dash input, action-grid, синхронизация первой даты блока.
- PWA: export содержит все новые icons/manifest entries и precache их включает.
- Manual iPhone: онлайн-вход → создание и отметка задач → закрыть PWA → включить авиарежим → открыть с экрана Домой. Ожидаются загрузочный статус, сохранённый email, прежние данные, локальные изменения и рост outbox; после возврата сети — sync без потери данных.
- Regression: focused Jest, `typecheck`, `lint`, PWA export и protected staging guard. Публикация staging всегда требует нового отдельного подтверждения.
