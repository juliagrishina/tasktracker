# Epic 01 — закрытие требований: дизайн

Дата: 2 августа 2026 г.  
Статус: согласовано для планирования и реализации.

## Цель

Довести Epic 01 до состояния, в котором все сущности MVP имеют одинаковый локальный контракт хранения на iPhone и в браузерном прототипе, доменные ограничения не зависят от платформы, а development-сборки показывают устойчивые тестовые данные во всех четырёх разделах.

## Границы

Входит в работу:

- чтение и запись проектов, задач, подзадач, напоминаний, блоков расписания, серий повторений, завершённых элементов и пользовательских настроек;
- преобразование напоминания с назначенным временем в самостоятельную задачу;
- единая проверка отношений «задача — подзадача» в SQLite и web in-memory data source;
- development-тестовые данные на iPhone и web, без дублей после повторного запуска;
- автоматические тесты и обновлённый чек-лист ручной проверки на iPhone.

Не входит:

- формы создания и редактирования, календарь, уведомления, синхронизация, Microsoft 365, iCloud, сервер и авторизация;
- пользовательские опасные действия: в Epic 01 их по-прежнему нет, поэтому отдельное подтверждение в интерфейсе не требуется.

## Архитектура

### Полный контракт хранения

`AppDataSource` получает операции `save`/`get` для всех восьми типов данных и `saveSettings`. Платформенные реализации используют одинаковые сигнатуры: Expo SQLite на iPhone и in-memory хранилище на web. Репозитории остаются единственной точкой доступа прикладного кода к данным.

У `Reminder` появится заголовок. При преобразовании напоминания прикладной use case создаёт самостоятельную задачу без проекта с тем же заголовком, удаляет исходное напоминание и возвращает созданную задачу. Идентификатор новой задачи передаёт вызывающий код; это делает операцию детерминированной и тестируемой без дополнительной библиотеки UUID.

### Инварианты

Перед сохранением подзадачи обе реализации находят её родителя и принимают только `TaskItem` с `kind: 'task'`. Поэтому нельзя создать подзадачу без родителя, подзадачу у подзадачи и четвёртый уровень вложенности ни в web-версии, ни на iPhone. SQLite-триггеры остаются второй линией защиты.

Напоминание не может иметь `projectId`; блок расписания всегда принимает `taskItemId`, поэтому к напоминанию он неприменим. Блоки проверяются на валидные даты, окончание позже начала и шаг пять минут.

### Тестовые данные и интерфейс

В development-режиме `seedDemoData` идемпотентно сохраняет фиксированные записи: два проекта, задачи для «Плана», задачи Backlog, завершённые элементы, напоминание, серию повторений, блоки расписания и изменённую настройку уведомления. Тестовые задачи показываются и в Expo Go на iPhone, и в `npm run web`; повторный запуск обновляет записи по стабильным идентификаторам, а не создаёт копии.

Экраны получают подготовленные данные из контейнера зависимостей. «План», Backlog и «Завершённые» показывают соответствующие демонстрационные карточки; «Настройки» показывают сохранённое тестовое значение настройки. В production-сборках демо-данные не создаются: «План» сохраняет исходное пустое состояние из базового ТЗ.

### Инициализация и платформы

Корневой контейнер завершает инициализацию базы, загрузку настроек и development-посев до передачи состояния экрану. В конфигурации приложения остаётся портретная ориентация и iPhone-only режим; ручной чек-лист требует проверку на iPhone с iOS 26 через Expo Go. Технически автоматически подтвердить реальный запуск на физическом устройстве в Windows-среде нельзя.

## Тестирование

До кода добавляются падающие тесты для:

1. сохранения и чтения каждого типа данных и изменённых настроек после повторной инициализации;
2. запрета несуществующего родителя и подзадачи у подзадачи в web data source;
3. преобразования напоминания в самостоятельную задачу с удалением исходного напоминания;
4. идемпотентного посева полного набора тестовых данных;
5. отображения тестовых карточек на всех четырёх экранах через общий контейнер.

После реализации выполняются `npm test`, `npm run typecheck`, `npm run lint` и `npm run web:export`. Ручная проверка на iPhone подтверждает портретный запуск, русские вкладки, тестовые данные после перезапуска и работу после отключения сети.

## Принятые решения

- Тестовые данные разрешены пользователем и существуют только в development-режиме; это явно отменяет прежнее требование о пустом «Плане» для development-версии на iPhone.
- Веб-хранилище остаётся временным: после обновления страницы данные исчезают, что соответствует техническому ограничению браузерного прототипа.
- Подтверждение физического запуска на iPhone остаётся критерием приёмки, который выполняется пользователем после готовности сборки.
