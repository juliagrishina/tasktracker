# Epic 01 — Каркас приложения и локальное хранилище: дизайн

Дата: 1 августа 2026 г.
Статус: согласовано для планирования реализации.

## Цель

Создать автономную основу iPhone-приложения: постоянную навигацию из четырёх вкладок, стартовый экран «План» и локальное хранилище, не зависящее от сети, учётной записи или Microsoft 365. Основа должна сохранить данные после перезапуска и дать последующим эпикам единый доступ к доменной модели через репозитории.

## Принятое решение

Приложение создаётся в корне репозитория из Expo Tabs template, на React Native, Expo Router и TypeScript в strict-режиме. Для ранней проверки на iPhone без Apple Developer Program выбирается совместимая с Expo Go ветка Expo SDK 54; переход на development build не входит в Epic 01.

Вкладки реализуются стандартным Expo Router `Tabs`, а не экспериментальными native tabs: API стабилен, четыре раздела соответствуют утверждённой структуре, а визуальная детализация будет добавляться по эпикам интерфейса. SQLite используется только за экранным слоем репозиториев; маршруты и компоненты не выполняют SQL-запросы напрямую.

## Рассмотренные варианты

1. **Expo Tabs + SQLite — выбран.** Даёт готовую файловую навигацию и минимальный объём конфигурации при сохранении чётких границ между UI и данными.
2. **Blank TypeScript + ручная настройка навигации.** Не выбран: потребует воссоздать Router-конфигурацию без пользы для MVP.
3. **Только development build на новой Expo SDK.** Не выбран для Epic 01: он преждевременно создаёт зависимость от Apple Developer Program и не улучшает локальный каркас.

## Границы эпика

### Входит

- Expo-проект в корне репозитория с TypeScript strict.
- Корневой layout и четыре постоянные вкладки: «План», Backlog, «Завершённые», «Настройки».
- Старт на вкладке «План» с дневным пустым состоянием.
- Инициализация SQLite, версионная миграция первой схемы и создание настроек по умолчанию.
- Доменные типы, ограничения и репозитории для проектов, задач, подзадач, напоминаний, блоков расписания, повторений, завершённых элементов и настроек.
- Тесты доменных ограничений, миграции и сохранения/чтения локальных данных.

### Не входит

- Создание и редактирование дел, Backlog, календарная шкала, повторения в интерфейсе, архив, энергия и уведомления.
- Microsoft 365, OAuth, Outlook, `expo-secure-store`, сервер, iCloud, вход и синхронизация.
- Перетаскивание, таймер, поиск, фильтры, аналитика и любые функции следующих эпиков.

## Архитектура

### Навигация и UI

`src/app/_layout.tsx` создаёт корневой stack и подключает группу `(tabs)` без дополнительной системной шапки. `src/app/(tabs)/_layout.tsx` объявляет четыре экрана. Маршрут `index.tsx` является вкладкой «План» и показывает название раздела, текущую дату и пустое состояние с объяснением, что первое дело появится в Backlog следующего эпика. Остальные три вкладки показывают нейтральные заглушки без обещания несуществующих действий.

Все подписи — на русском, кроме утверждённого названия `Backlog`. Навигация не содержит экранов входа или элементов Microsoft 365. Корневой layout ожидает завершения инициализации базы, чтобы экраны не работали с непроинициализированной схемой.

### Доменные данные

Доменные типы находятся в `src/domain`. На уровне данных задача и подзадача представлены одним типом work item с различающимся `kind`; подзадача обязательно ссылается на задачу-родителя, а задача не имеет родителя. Проект — только верхний контейнер. Напоминание не ссылается на проект и не может иметь собственный блок расписания: назначение точного времени в дальнейшем будет преобразовывать его в задачу.

Первая миграция создаёт таблицы для проектов, work items, напоминаний, блоков расписания, серий повторений, завершённых записей и настроек. Блок расписания ссылается только на задачу или подзадачу. Ограничения `CHECK`, внешние ключи и SQLite-триггеры защищают инварианты, которые нельзя выразить одним `CHECK`, в частности запрет дочерних элементов у подзадачи. Таблицы Microsoft 365 и токенов не создаются.

Настройки создаются ровно один раз с начальными значениями: рабочий диапазон 08:00–22:00, вечерняя проверка 21:00, уведомление за 10 минут. Часовой пояс определяется устройством и не хранится как редактируемая пользовательская настройка.

### Доступ к данным

`src/data/database` отвечает только за открытие SQLite и выполнение миграций. `src/data/repositories` предоставляет типизированные операции чтения и записи доменных сущностей. UI обращается к use case или репозиторию через единый контейнер зависимостей; прямые импорты `expo-sqlite` из файлов в `src/app` запрещены.

Миграции выполняются транзакционно, имеют монотонный номер версии и безопасно запускаются при каждом старте. Повторный запуск миграции не создаёт повторных строк настроек и не удаляет сохранённые данные.

## Проверяемые правила

- Проект не может иметь родителя.
- Задача может принадлежать проекту либо не иметь проекта; она не может быть дочерней у другой задачи.
- Подзадача обязана иметь задачу-родителя и не может иметь собственных потомков.
- Напоминание не может принадлежать проекту и не получает точный блок расписания.
- Блок расписания хранит начало и конец с шагом пять минут и может принадлежать только задаче или подзадаче.
- Вторая и последующие инициализации базы сохраняют ранее записанные сущности и не дублируют настройки по умолчанию.

## Тестирование

До производственного кода создаются unit-тесты для каждого перечисленного доменного правила. Отдельные тесты проверяют миграцию чистой базы, повторную инициализацию, настройки по умолчанию и сохранение/чтение тестового проекта и задачи. Тесты располагаются вне `src/app`, поскольку файлы маршрутов Expo Router не должны смешиваться с тестовыми файлами.

До завершения Epic 01 необходимо запустить lint, TypeScript-проверку, все unit-тесты и Expo export/bundle-проверку. Практическая проверка на iPhone через Expo Go подтверждает запуск, русские названия четырёх вкладок, старт на «Плане» и сохранение тестовой записи после перезапуска приложения.

## Ограничения и риски

- Expo Go подходит для навигации и SQLite, но не является заменой development build для будущих нативных возможностей. Это не блокирует Epic 01.
- Локальная база будет удалена вместе с приложением; резервное копирование и iCloud не добавляются.
- Исходное ТЗ описывало ранний риск Microsoft 365, но согласованная карта эпиков переносит эту проверку в условный Epic 07. Epic 01 от неё не зависит.
