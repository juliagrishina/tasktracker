# Epic 03 — завершение планирования, повторений и расчёта загрузки

**Статус:** согласовано с пользователем 13 августа 2026 года.

## Цель и границы

Этот документ завершает только Epic 03 из
`docs/tz/epic-03-scheduling-recurrence-and-calculations.md`. Он устраняет
выявленные пробелы реализации и делает планирование доступным из реальных
пользовательских сценариев. Работа не добавляет синхронизацию Outlook,
уведомления, архив, drag-and-drop или фактический учёт времени.

Визуальный ориентир — приложенные примеры системного календаря iOS: понятные
строки начала и окончания, календарь для даты и выбор значений вместо ручного
набора. Это ориентир поведения, а не попытка копировать системный интерфейс
пиксель-в-пиксель.

## Поведение планирования

У задачи и подзадачи будет единый блок «Планирование», а не отдельный раздел
«Временные блоки»:

- выбор «Без даты», «Дата» или «Период»;
- нажатие на дату открывает календарь с выбором месяца и дня; дата также
  отображается в однозначном локальном формате `ДД.ММ.ГГГГ`;
- у даты можно задать необязательное время: начало и окончание выбираются из
  сетки в пять минут, без свободного текстового ввода;
- у периода начало и окончание выбираются тем же календарём;
- несколько точных интервалов остаются поддержанным сценарием задачи, но
  добавляются внутри этого блока как дополнительный интервал, а не как
  самостоятельный раздел;
- оценка длительности выбирается из доступных значений с шагом пять минут, а
  не вводится вручную.

Кнопка «Запланировать» из карточки backlog открывает эту же форму. Она не
показывает заглушку. Напоминание получает явное действие планирования и может
быть сохранено без точного времени; при выборе точного времени остаётся
подтверждаемое атомарное преобразование в задачу.

При повторном открытии формы она строится из сохранённой даты, периода,
оценки, блоков и повтора. Поэтому редактирование не сможет неявно превратить
задачу с датой в задачу без даты. Для уже запланированной записи кнопка формы
будет «Сохранить».

## Загрузка дня

Загрузка дня равна сумме следующих вкладов, делённой на рабочую вместимость из
настроек. Процент не ограничивается 100 %.

1. Каждый точный временной блок вносит только реальную часть своего интервала,
   попавшую в рассматриваемые локальные сутки. Блок, пересекающий полночь,
   делится между двумя днями.
2. Оценка задачи или напоминания без точного времени вносится в тот день, на
   который оно запланировано.
3. Для периода без точного времени общая оценка распределяется поровну между
   всеми днями периода включительно. Округление минут сохраняет общую оценку.
4. У повторяющейся записи без точного времени оценка учитывается в день каждого
   активного экземпляра. Если у записи есть точный блок, её оценка дополнительно
   не суммируется.
5. Запись без даты и периода не влияет на загрузку.

Такой расчёт применяется одинаково к задачам, подзадачам и напоминаниям, а
также в дневном, недельном и месячном представлениях. Пересечения по-прежнему
не вычитаются: это реальная сумма обязательств пользователя.

## Повторяющиеся экземпляры

Экземпляр серии получает полноценный контекст и в списке плана, даже если у
него нет точного времени. Для него доступны три независимые операции:

- «Завершить этот экземпляр» — экземпляр больше не показывается в плане и не
  влияет на загрузку;
- «Отменить этот экземпляр» — такой же результат для плана, но с отдельным
  статусом отмены;
- изменение даты, периода, оценки или времени — создаёт исключение только для
  выбранного экземпляра. Операция над серией меняет правило всей серии.

Исключение переносимого экземпляра скрывает исходную дату и показывает запись
на новой дате (либо на днях нового периода). Это применяется и к задачам, и к
напоминаниям. Повтор серии поддерживает `daily`, `weekly` и `monthly` с
положительным интервалом.

Модель исключения хранит статус `active`, `cancelled` или `completed`, время
завершения и типизированное изменение владельца: для задачи/подзадачи либо для
напоминания. Хранилища SQLite и in-memory соблюдают один контракт и одно
ограничение уникальности пары `(seriesId, occursOn)`.

## Время, часовые пояса и данные

Точный блок хранит абсолютные ISO-моменты и идентификатор часового пояса,
полученный при создании. Для старых записей без идентификатора сохраняется
совместимое поведение на основании ISO-смещения. При разворачивании повтора
локальное время блока остаётся тем же в его сохранённой зоне; дата и смещение
пересчитываются для перехода летнего/зимнего времени. Границы дня и расчёт
блока через полночь используют эту зону.

Миграция базы расширяет существующие таблицы без удаления данных: добавляет
поле зоны блока, статус завершения/время завершения и данные исключения
напоминания. Браузерный источник данных будет повторять SQLite-контракт, в том
числе запрет двух исключений на одну дату серии.

## Валидация и ошибки

Форма проверяет до создания или изменения основной записи:

- существование всех дат (включая високосный год), порядок границ периода и
  попадание даты экземпляра в корректный календарный сценарий;
- положительный интервал повтора;
- точное время и длительность на пятиминутной сетке;
- окончание точного блока позже начала.

Та же проверка остаётся на уровне domain/use-case, чтобы некорректные данные не
могли попасть в хранилище обходным путём. Конфликты блоков остаются
предупреждением до сохранения, без дублирования одного и того же сообщения.

## Проверки при приёмке

Покрываются domain, use-case, data-source и UI сценарии:

- дата, период, точное время и оценка через селекторы; редактирование сохраняет
  все эти значения;
- оценка без времени для даты, периода и повтора меняет загрузку дня; оценка
  при наличии блока не считается дважды;
- перенос, отмена и завершение одного экземпляра задачи и напоминания;
- повтор `daily`/`weekly`/`monthly`, границы месяца, високосный год, DST и блок
  через полночь;
- одинаковая уникальность исключений в SQLite и in-memory;
- переход из backlog в рабочую форму планирования и преобразование напоминания
  в задачу при точном времени.

Перед сдачей запускаются `npm test`, `npm run typecheck`, `npm run lint` и
`npm run web:export`, затем вручную проверяется веб-путь создания, изменения и
отображения загрузки.
