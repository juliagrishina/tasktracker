# Epic 03 on the current local-first architecture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete current Epic 03 scheduling, recurrence, conflicts and exact-block load without undoing the multi-user, local-first and soft-delete architecture.

**Architecture:** Work from `origin/main` rather than the old Epic 03 branch. Business planning data stays in local SQLite/in-memory `AppDataSource`; Supabase remains limited to anonymous identity and best-effort append-only events. New schedule/recurrence records follow the existing `updatedAt`/`deletedAt` lifecycle, while recurrence exceptions keep independent cancellation, completion and block overrides.

**Tech Stack:** TypeScript, Expo 54, React Native, Expo SQLite, Supabase JS client, Jest and React Native Testing Library.

**Spec:** `docs/handoffs/epic-03-resume.md`, `docs/tz/account-data-and-cloud-architecture.md`, `docs/tz/epic-03-scheduling-recurrence-and-calculations.md`.

## Global Constraints

- Do not merge, rebase, modify or delete `codex/epic-03-scheduling` or its worktree/WIP.
- Do not restore `CompletedItem`/`completed_items`; completion source of truth is `completedAt`.
- User-visible delete operations for planning records are soft deletes using `deletedAt` and explicit related-row effects, not FK cascade or SQL `DELETE`.
- Task and subtask scheduling is through one or more exact blocks; reminders own date, period, repeat and estimate.
- Exact start and end values use a five-minute grid; a new block defaults to the nearest future slot and 60 minutes.
- Day load is only exact own scheduled-block minutes divided by configured available workday minutes; estimates without an exact block do not contribute under the current Epic 03 specification.
- Local write completes first. `task_scheduled`, `task_rescheduled` and `task_unscheduled` events are fire-and-forget only after a successful local task/subtask operation; Supabase failure never blocks or rolls back the operation.
- No sync engine, cloud business tables, backup/restore, multi-device, account UI, Outlook writes or unrelated TECH_DEBT work.
