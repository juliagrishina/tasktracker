# Epic 01 — Каркас приложения и локальное хранилище

**Приоритет:** must-have · **Порядок реализации:** 1 из 9

> **Актуализация Epic 11.** Исходное описание первого запуска без регистрации ниже является историческим scope Epic 01. Для текущего продукта [«Аккаунт, email-авторизация и облачная синхронизация»](account-authentication-and-cloud-sync.md) заменяет правила доступа, запуска и web-постоянства: вход в рабочую область возможен после регистрации или входа; после первого успешного онлайн-входа account-scoped локальная реплика должна открываться и работать offline. Четыре вкладки, локальная модель и авиарежим сохраняются для авторизованного пользователя. Production web persistence перенесён в IndexedDB по E11-T28.

## Цель эпика

Создать устойчивую основу offline-first приложения: четыре основных раздела, единый стиль интерфейса и локальное хранение данных. После первой успешной онлайн-авторизации пользователь может вести дела без подключения к сети.

## Пользовательские сценарии

- Как пользователь, я хочу сразу открыть приложение и увидеть понятное нижнее меню, чтобы перейти к нужному разделу без обучения.
- Как пользователь, я хочу, чтобы мои дела и настройки сохранялись на телефоне после закрытия приложения, чтобы не терять план.
- Как пользователь, я хочу после первого входа пользоваться приложением без интернета, чтобы продолжать работу и не зависеть от сети.

## Функциональные требования

1. Приложение должно запускаться на iPhone с русским интерфейсом и портретной ориентацией.
2. Нижняя навигация должна постоянно содержать четыре раздела: «План», «Backlog», «Завершённые» и «Настройки».
3. При первом запуске должен открываться раздел «План» в дневном представлении; пустое состояние должно направлять пользователя к созданию первого дела.
4. Данные должны храниться локально и быть доступны без сетевого подключения.
5. В модели данных должны поддерживаться: проекты, задачи, подзадачи, напоминания, блоки расписания, серии повторений и настройки пользователя. Завершённость проекта, задачи, подзадачи и напоминания — это состояние самой сущности (поле `completed_at`), а не отдельная сущность архива (см. [«Аккаунт, данные и облачная архитектура»](account-data-and-cloud-architecture.md)).
6. Проект должен быть верхним уровнем и не может быть дочерним элементом другого проекта.
7. Задача должна принадлежать проекту либо существовать без проекта; задача может иметь подзадачи.
8. Подзадача должна быть последним уровнем и не может иметь собственных дочерних элементов.
9. Напоминание должно существовать вне проектов и при назначении конкретного времени уметь преобразовываться в задачу.
10. Интерфейс не должен показывать технические внутренние статусы сущностей; пользователь видит только действия и понятный результат.
11. Для опасных или необратимых действий должны использоваться системно понятные подтверждения.
12. Браузерный прототип должен запускаться командой `npm run web` и показывать четыре вкладки с тем же стартовым путём, что и приложение на iPhone.

## Критерии приёмки

- [ ] После первой успешной онлайн-авторизации приложение повторно открывается с валидной сохранённой сессией без сети; основная функциональность доступна в локальной account-scoped области.
- [ ] Из любого основного раздела доступны все четыре пункта нижнего меню.
- [ ] Созданные тестовые сущности и изменённые настройки сохраняются после перезапуска приложения.
- [ ] Приложение остаётся работоспособным в авиарежиме.
- [ ] Модель не позволяет создать четвёртый уровень вложенности или подзадачу с дочерними элементами.
- [ ] При отсутствии или истечении сессии показывается Auth; рабочая область, legacy-данные и данные другого аккаунта не открываются до успешного входа.
- [ ] В браузере на Windows открывается интерактивный прототип с четырьмя вкладками и стартовым экраном «План».

## Технические детали и ограничения

- Использовать React Native + Expo CNG + TypeScript со строгой типизацией.
- Навигацию строить на Expo Router; локальную базу — на Expo SQLite с миграциями схемы.
- Доступ к данным должен идти через слой репозиториев и сценариев приложения, а не напрямую из экранов.
- На web production persistence использует IndexedDB для account-scoped реплики; in-memory data source допустим только в тестах и демонстрационных средах. iPhone использует Expo SQLite.
- UI входа/регистрации и account policy определяются Epic 11; iCloud и обмен данными между пользователями исключены из MVP. Историческая фоновая анонимная идентичность описана в [«Аккаунт, данные и облачная архитектура»](account-data-and-cloud-architecture.md) и не является пользовательским режимом.
