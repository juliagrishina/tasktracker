# Epic 02 — Backlog, проекты и управление делами

**Приоритет:** must-have · **Порядок реализации:** 2 из 9

## Цель эпика

Дать пользователю единое место для фиксации и организации всего, что ещё не поставлено в календарный план. Backlog решает проблему «не забыть» без необходимости сразу выбирать дату и время.

## Пользовательские сценарии

- Как пользователь, я хочу быстро добавить задачу только с названием, чтобы сохранить мысль за несколько секунд.
- Как пользователь, я хочу создавать проекты и раскладывать задачи по ним, чтобы видеть структуру работы.
- Как пользователь, я хочу добавлять подзадачи, чтобы разбивать крупное дело на выполнимые шаги.
- Как пользователь, я хочу завести напоминание без проекта, чтобы хранить личные обязательства отдельно от задач.

## Функциональные требования

1. Раздел Backlog должен показывать незапланированные элементы в фиксированном порядке: напоминания без даты, задачи без проекта, затем проекты с их задачами.
2. В Backlog не должны быть доступны поиск и фильтры.
3. Пользователь должен иметь возможность создать проект с обязательным названием и необязательным описанием.
4. Пользователь должен иметь возможность создать задачу с обязательным названием, а также при необходимости выбрать проект, описание, длительность и подзадачи.
5. Пользователь должен иметь возможность создать напоминание с обязательным названием и необязательными датой, периодом, повторением и оценкой длительности.
6. В Backlog у незапланированной задачи не должно быть обязательной даты или времени.
7. Пользователь должен иметь возможность редактировать название, описание, проект, длительность и состав подзадач у незавершённых элементов.
8. Пользователь должен иметь возможность перемещать задачу между проектом и категорией «Без проекта».
9. Пользователь должен иметь возможность создавать, редактировать и удалять подзадачи только у задачи; подзадача не должна содержать вложенных элементов.
10. Пользователь должен иметь возможность вручную завершить проект; это действие не должно автоматически завершать его задачи.
11. Удаление незавершённого проекта, задачи, подзадачи или напоминания должно требовать подтверждения и не должно затрагивать несвязанные сущности.
12. Экран детали должен предоставлять понятные действия для редактирования, планирования и завершения элемента, если они применимы.
13. В браузерном прототипе должны быть интерактивно доступны все экраны и пользовательские пути этого эпика, включая создание и организацию тестовых данных.

## Критерии приёмки

- [ ] Можно создать проект, задачу без проекта, задачу внутри проекта и напоминание, указав только обязательное поле названия.
- [ ] Backlog выводит категории в согласованном порядке и не содержит поиска или фильтров.
- [ ] Задача может иметь подзадачи, но создание дочернего элемента у подзадачи недоступно.
- [ ] Задачу можно перенести в проект и обратно без потери её данных.
- [ ] Завершение проекта не меняет состояние задач, которые в него входят.
- [ ] Деструктивное удаление требует явного подтверждения.
- [ ] Через `npm run web` можно пройти основные сценарии Backlog на временных данных без открытия iPhone-приложения.

## Зависимости от других эпиков

- Зависит от Epic 01: сущности, хранение и навигация.
- Передаёт задачи и напоминания в Epic 03 для назначения времени.

## Технические детали и ограничения

- Все изменения должны записываться в локальную SQLite-базу через доменные сценарии.
- Форма создания должна валидировать обязательное название и не требовать дату для Backlog.
- Сортировка и иерархия должны быть детерминированными, чтобы порядок не менялся после перезапуска.
- Браузерный прототип использует тот же UI и контракты репозиториев; постоянное хранение в браузере не является требованием MVP.
- Импорт, совместное редактирование и файловые вложения не входят в MVP.
