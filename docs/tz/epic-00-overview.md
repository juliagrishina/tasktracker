# MVP — карта эпиков

Этот комплект документов фиксирует согласованный объём MVP приложения-планировщика. Основной продукт должен быть полезен полностью автономно и не требовать от пользователя регистрации, входа или интеграции с Microsoft 365 для начала работы. Модель идентичности пользователя, владения данными и облачной архитектуры зафиксирована отдельно в документе [«Аккаунт, данные и облачная архитектура»](account-data-and-cloud-architecture.md) и является для неё единым источником истины — при расхождении с формулировками ниже приоритет за тем документом. Эпики 07–08 выполняются только как необязательная ветка после подтверждения технической возможности.

## Первый post-MVP Epic

После выпуска MVP 1.0 выполняется [Epic 10 — Рекомендательная система: ИИ-советник-аналитик](epic-10-ai-advisor-and-analytics.md). Это обязательный post-MVP Epic версии 1.1: он использует накопленную историю планирования, выполнения и энергии для объяснимых рекомендаций, вечерней рефлексии и аналитических отчётов. Epic 10 не расширяет состав MVP 1.0 и не меняет положение Epic 09 как релизного эпика MVP.

## Правило для Microsoft 365

Эпик 07 проводится поздно и не является блокером для основного MVP. Если корпоративная политика, tenant или доступ к тестовой учётной записи не позволяют корректно пройти авторизацию, результат фиксируется как **no-go**, Эпик 08 не реализуется, а приложение выпускается без интеграции с Microsoft 365, сохраняя весь основной функционал.

## Браузерный прототип — обязательный результат

Каждый эпик должен иметь работающий интерактивный результат, доступный через `npm run web` на Windows. Прототип использует общие маршруты и компоненты с iPhone-приложением и позволяет проверить утверждённый пользовательский путь. Нативные возможности — постоянная SQLite-база, уведомления, защищённое хранение, авторизация Microsoft 365 и реальная синхронизация Outlook — дополнительно проверяются на iPhone и не подменяются браузером.

## Общие рамки MVP

- Платформа: iPhone, iOS 26+, портретная ориентация, русский интерфейс.
- Технологии: React Native, Expo (CNG), TypeScript в strict-режиме, Expo Router, Expo SQLite.
- Основные бизнес-данные (проекты, задачи, напоминания, расписание, настройки) в MVP хранятся локально на устройстве и не синхронизируются между устройствами; совместный доступ к данным не поддерживается. Модель идентичности пользователя и облачной инфраструктуры описана в [«Аккаунт, данные и облачная архитектура»](account-data-and-cloud-architecture.md).
- Нижнее меню постоянно содержит четыре раздела: «План», «Backlog», «Завершённые», «Настройки».
- Интеграция Outlook, если будет включена, работает строго на чтение; разрешения и сценарии записи в Microsoft Graph не допускаются.
