# Epic 08 — Интеграция Outlook

**Приоритет:** nice-to-have, условный · **Порядок реализации:** 8 из 9

## Цель эпика

Показать занятость из Outlook рядом с личным планом, не меняя корпоративный календарь и не превращая приложение в клиент Outlook. Эпик реализуется только после успешного вывода go в Epic 07.

## Пользовательские сценарии

- Как пользователь, я хочу видеть события своего Outlook в плане, чтобы не ставить личные блоки поверх рабочих встреч случайно.
- Как пользователь, я хочу вручную обновить календарь, если расписание изменилось, чтобы видеть актуальную занятость.
- Как пользователь, я хочу отключить Outlook и удалить его локальный кэш, чтобы снова использовать приложение исключительно локально.
- Как пользователь, я хочу открыть сведения о событии Outlook, не рискуя изменить его из приложения.

## Функциональные требования

1. Реализация разрешена только при принятом результате go из Epic 07; при no-go интерфейс и код интеграции не включаются в релиз MVP.
2. Интеграция должна использовать только delegated permission `Calendars.Read` и выполнять в Microsoft Graph только операции чтения.
3. В настройках пользователь должен иметь возможность подключить учётную запись, переподключить её, отключить её и удалить локальный кэш Outlook.
4. После первого подключения приложение должно загрузить события как минимум за период от 7 дней до текущей даты до 30 дней после неё.
5. Дальнейшее обновление должно поддерживать чтение `calendarView`, постраничную обработку и delta-синхронизацию, если она доступна для выбранного сценария API.
6. Пользователь должен иметь возможность запустить ручное обновление; фоновое обновление допускается как best effort не чаще одного раза в час и не должно быть критичным для работы приложения.
7. На плане события Outlook должны быть визуально отделены от собственных блоков и доступны только для просмотра.
8. В деталях внешнего события должны отображаться доступные данные: название, время, описание, организатор, участники, место и ссылка Teams, если они получены API.
9. Должны корректно обрабатываться отменённые, перенесённые, повторяющиеся и вседневные события.
10. Ошибки сети, истёкшая сессия, отказ в доступе и частичная синхронизация должны быть понятны пользователю и не должны повреждать локальный план.
11. Отключение учётной записи должно удалить токены из защищённого хранилища и локальный кэш Outlook, не затрагивая проекты, задачи, напоминания и настройки пользователя.
12. Пользователь не должен иметь возможности создавать, изменять, удалять или отвечать на события Outlook из приложения.

## Критерии приёмки

- [ ] Интеграцию можно включить только после успешного результата Epic 07.
- [ ] После подключения в плане отображаются события Outlook из согласованного периода, а собственные задачи остаются отдельными.
- [ ] Ручное обновление добавляет изменения, переносы и отмены без дублирования событий.
- [ ] Открытие события Outlook не содержит действий редактирования, удаления, RSVP или записи в календарь.
- [ ] Ошибка синхронизации видима пользователю, но локальные задачи и план остаются доступными офлайн.
- [ ] Отключение учётной записи удаляет её токены и кэш, но не удаляет пользовательские данные приложения.
- [ ] Проверка запросов подтверждает отсутствие Microsoft Graph операций записи.

## Технические детали и ограничения

- Использовать Microsoft Graph с минимальными scopes, проверенными в Epic 07; не расширять их без отдельного решения по продукту и безопасности.
- Токены хранить в `expo-secure-store`, кэш внешних событий — локально в SQLite с отделением от пользовательских сущностей.
- Синхронизация должна быть идемпотентной, устойчивой к страницам API и возобновляемой после ошибки.
- Интеграция предназначена для одного выбранного календарного контекста пользователя; управление несколькими учётными записями не входит в MVP.
